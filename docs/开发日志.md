## 2026-09-09 · v0.2.0 一体化桌面软件「续火花控制台」

**动机**：用户反馈"不能做一堆脚本让用户按，应该集成一个软件"。脚本集合 → pywebview 桌面应用。

**架构**：software/ = main.py（pywebview 窗口 + Api 桥接）+ backend/（douyin/qq/scheduler/updater/logger/winproc 六模块）+ ui/（七页面单页应用：仪表盘/抖音/QQ/话术库/定时/日志/关于）。

**关键实现**：
- 界面内抖音扫码登录：login_gui.py 轮询 sessionid Cookie，成功自动保存凭证（去掉了上游"回终端按回车"的交互）
- QQ 配置直写 `tools/napcat/shell/config/napcat-plugin-auto-tasks.json`（NapCat 未首跑时写默认约定路径，启动 QQ 时自动同步部署插件 dist）
- 事件总线日志：logger.py 三路输出（UI 状态栏 / 仪表盘动态 / logs/日期-software.log）
- 计划任务入口迁至 software/backend/daily_douyin.ps1，已重新注册
- 桌面快捷方式「续火花控制台」+ icon.ico（星星布丁-想你）

**踩坑**：
- Windows 控制台程序输出 GBK，强制 UTF-8 解码会炸 reader 线程 → winproc.run_cmd 双编码保险，全后端统一走它
- pywebview 6.x 无 __version__ 属性（安装成功但自检误报失败）

**测试**：API 直调全绿；dry-run 经软件调度层实跑成功（12.4s，登录态有效，找占位好友失败属预期）；窗口启动验证通过；QQ 配置写入/读回一致。

**下一步候选**：见 TODO 🟡 区（QQ 开机自启、失败通知、分好友话术池、exe 打包）。

## 2026-09-09 · v0.3.0 对抗评审大修

四路子 Agent 并行评审（后端/前端/小白UX/集成实测），关键发现与修复：
1. **QQ 侧整条链路空转**（两路独立发现）：插件真实配置在 config/plugins/<id>/config.json 且需 plugins.json 显式启用——逆向 napcat.mjs 铁证。软件此前写的是自造文件。
2. **pythonw 闪黑框**：评审 agent 用 EnumWindows 实测 tasklist 每 3.2s 弹窗。统一 CREATE_NO_WINDOW。
3. **PS5.1 Stop+2>&1 陷阱**：第一条 stderr 即终止整次定时运行，复现确认。
4. **保存按钮清空插件配置**：前端只回传 8 字段+后端白名单重建=数据丢失。改合并式。
5. **占位好友**：被当已配置，正式发送前无拦截。已加三重防护。
6. **修复过程中又抓到自己两个**：run_cmd 不支持 env 导致坏配置校验被绕过写盘（回归测试抓到）；脏检查判错方向（GUI 目视抓到）。两处均已修+复测。

评审估算小白上手成功率 40%（修 P0 后 75-85%）。本版目标：静默失败全部消灭——要么成功，要么人话报错。
