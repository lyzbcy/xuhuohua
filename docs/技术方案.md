# 技术方案

```
      ┌────────▼────────┐ ┌──────▼──────────────┐

      │ douyin-auto-fire │ │ NapCat v4.18.19     │

      └─────────────────┘ └─────────────────────┘
```

## 关键决策

### 为什么抖音侧选 douyin-auto-fire 而不是 DouYinSparkFlow？

| 维度 | douyin-auto-fire（选中） | DouYinSparkFlow（备选） |
|------|------------------------|------------------------|
| 维护 | 2026-09-04 仍在更新 | 2026-08-31 |
| 演练模式 | 有 dry-run，防误发 | 无 |
| 随机话术 | `random` + `choices` 原生支持 | 一言 API |
| 图片消息 | PNG/JPG/GIF/WEBP | — |
| 部署 | Actions/Docker/Win/服务器 | 同 |
| 备注 | — | README 明确警告 Actions 部署易被踢下线 |

DouYinSparkFlow 保留在 `DouYinSparkFlow/` 目录作为备胎：若主力失效（页面选择器过时等），切备选。

### 为什么 QQ 侧用 NapCat 插件而不是独立脚本？

QQ 没有 Douyin 那样的网页私信入口，必须走协议端。NapCat 是当前最活跃的 NTQQ 协议端实现；`napcat-plugin-auto-tasks` 插件内置 `friendSpark`（好友续火花）/`groupSpark`（群续火花）定时任务，支持 CQ 码（可发表情/图片），正好覆盖需求。

### 0 token 如何保证？

- 抖音：`config.json` 里 `random` 类型 + `choices` 数组 → 运行时 `random.choice` 抽取
- QQ：插件配置里的 `friendSpark_message` 支持多条/CQ 码
- 全链路无 LLM API 调用，无任何 API key

### 跨平台（Win/Mac 兼容，依据 ios与win兼容架构.md）

核心组件全跨平台：Python（douyin-auto-fire）、Node（NapCat）。Windows 专属的只有 `.bat` 包装和 `schtasks` 定时；Mac 上等价命令已写入 `docs/部署指南.md` 附录。

## 版本与更新（依据 自适应更新检测.md）

- 本项目版本：根目录 `VERSION` + `CHANGELOG.md`
- 更新入口：`scripts/检查更新.bat` → `update-check.ps1`（git fetch 比对 → ff-only pull → 依赖同步；失败提示重试；开代理提醒）
- 个人配置全部位于上游 `.gitignore` 清单内，更新永不覆盖
