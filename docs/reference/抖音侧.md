# reference · 抖音侧（douyin-auto-fire）

> 深入改抖音侧行为前读这个。源码在 `douyin-auto-fire/`（上游仓库，278★）。

## 运行原理

Playwright 驱动 Chromium 打开 `https://www.douyin.com/chat`，用 `storage-state.json`（扫码登录产物）恢复登录态 → 按配置里的好友名在左侧会话列表定位 → 打开会话 → 发消息（文字/图片/原生表情）→ 逐好友循环。

## 关键文件

| 文件 | 作用 |
|------|------|
| `run.py` | 入口；无 `config/accounts.json` 时单账号模式 |
| `app/config.py` | 配置解析；`TASK_CONFIG` 环境变量可指定任务文件 |
| `app/sender.py` | 发送逻辑：文字输入、图片 `set_input_files`、原生表情点击 |
| `app/selectors.py` | 页面元素选择器 —— **抖音改版时要改这里** |
| `app/browser.py` | 启动浏览器；`HEADLESS` 环境变量控制有头/无头 |
| `app/history.py` | 防重复发送的本地记录 |
| `scripts/login.py` | 扫码登录 → 生成 `storage-state.json` |
| `artifacts/run.log` | 每次运行的详细日志（排障第一现场） |

## 配置模型（app/models.py）

```
TaskConfig
 ├─ targets: Target[]          # 每个好友一个
 │   ├─ name: str              # 聊天列表显示名（备注优先）
 │   └─ messages: Message[]    # 依次发送；random 类型 = 抽一条
 ├─ Message.type: text | image | douyin_sticker | random
 │    text:  {"type":"text","content":"..."}
 │    image: {"type":"image","path":"stickers-lb/xx.png"}   # 相对 config.json 所在目录
 │    sticker:{"type":"douyin_sticker","sticker":"比心"}     # 可用: 比心/开心（config/stickers.json）
 │    random:{"type":"random","choices":[...]}               # 不可嵌套
 └─ send_interval_seconds: {min,max}   # 好友间隔随机秒数（拟人）
```

## 多账号

`config/accounts.json` 存在即进入多账号模式，每账号一个 `.env.accountN`（Cookie）+ `config/tasks/accountN.json`（任务）。当前未启用。

## 常见排障

### 云端会话写回与升级（2026-10-16 · v0.14.2）

- `app/auth_state.py` 在私信页验证通过后保存最新 storage_state；正常结束再次验证并保存，失败认证不覆盖；原子替换、600、保留旧快照和原 owner，防止覆盖其他进程的新登录。
- 登录脚本与定时发送共用 run.lock。登录必须验证私信页，再关闭完整 Chromium，由 `login-douyin.sh` 调用统一 Headless Shell 入口独立演练；首页看似登录、文件存在都不足以验收。
- 旧版静默更新不会更新引擎。将同一 Release 的 Skill 升级后，以 cron 用户执行 `python3 xuhuohua-cloud/scripts/upgrade-douyin-auth.py /绝对路径/xuhuohua-cloud.zip`。脚本验证旁边的 SHA-256 文件、版本、任务锁，仅更新 3 个公开认证文件，有备份与回滚。
- 已失效 Cookie 不会因代码升级恢复，需要人工登录。不能承诺长期不掉线；不可修改评论自动回复等其他应用的 profile，也不可为测试自动补发。

### 云端每日失败复盘（2026-10-07 · v0.14.1）

现状：已修复；维护：项目维护者；更新：2026-10-07。

- 同目录 root 新任务与 ubuntu 旧任务都在 09:00 运行，互相抢锁；旧入口指定 9/28 父目录登录态，9/30 新登录写入引擎目录却未被旧入口采用。新登录态演练 6/6 好友可打开，旧文件出现登录页。
- root 的通知状态为 600，ubuntu 并行通知报 PermissionError。修复采用原 QQ/通知用户 root 的唯一抖音入口，不放宽凭证权限、不改 QQ cron。
- ERR_NETWORK_CHANGED 没有导航重试；历史独占创建文件锁可能因异常退出残留。新代码仅重试导航临时网络错误，并在 Linux 使用 flock，稳定 inode 不删除。
- `run-douyin.sh` 是云端统一入口，优先引擎目录登录态；`install.sh` 清理本目录旧 cron 并注册一次。升级公开引擎源码与 Skill 脚本，不覆盖私有配置、历史、登录态。
- 验收分开记录：测试与 dry-run 不发送消息；真实发送以次日定时结果和聊天记录确认作为证据，不能把演练当发送成功。
- 正式入口还误用完整 Chrome 无头模式，能搜索但聊天不挂载；独立对照 Headless Shell 可打开聊天。`prepare-douyin.sh` 现在按 venv 的 revision 分别配置登录 Chromium/运行 Shell，不再按缓存目录最高版本选择。必须用实际 cron 的用户与入口做 dry-run，而非只凭临时探针通过。

1. **找不到好友**：昵称与聊天列表显示不完全一致；备注名最稳
2. **登录失效**：重跑 `scripts\douyin-login.bat`
3. **选择器失效**（抖音改版）：dry-run 卡在定位 → 看 `artifacts/` 下的截图 → 改 `app/selectors.py`
4. **看详细过程**：`.env` 里临时改 `HEADLESS=false`，能看到浏览器操作全过程
